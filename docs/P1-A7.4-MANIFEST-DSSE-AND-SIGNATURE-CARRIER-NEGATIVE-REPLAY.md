# P1-A7.4 — Manifest, DSSE and Signature-Carrier Negative Replay

P1-A7.4 is an additive negative-replay slice inside the draft P1-A7 interoperability layer. It consumes the exact checked-in P1-A2 bundle and public key, but it does not modify or replace the P1-A2, P1-A5 or P1-A6 authorities.

The replay extracts the exact P1-A2 DSSE envelope and supplied Ed25519 SubjectPublicKeyInfo. No private key is present or required.

## Portable carrier

The generated A7.4 carrier contains:

```text
standard
profile
manifest.members
dsseEnvelope
publicKeyPem
```

The ordered manifest contains exactly:

```text
payload
signature
public-key-spki
```

Each member is bound by SHA-256 and byte length. The order is authoritative and is checked before cryptographic acceptance.

## Boundary order

Every route evaluates the same bounded order:

```text
manifest membership, order and identities
DSSE envelope shape and canonical base64
closed payloadType
single Ed25519 signature carrier and keyid
Ed25519 verification over exact DSSE PAE
```

A manifest failure precedes signature failures when both defects are present. A valid carrier ends at the `signature` boundary.

## Negative vectors

The corpus contains nine vectors:

| Vector | Portable result |
| --- | --- |
| missing signature manifest member | `manifest.invalid` |
| swapped manifest member order | `manifest.invalid` |
| wrong payload manifest digest | `manifest.invalid` |
| wrong DSSE payload type | `signature.malformed` |
| payload-byte change with refreshed manifest identity | `signature.invalid` |
| truncated signature with refreshed manifest identity | `signature.malformed` |
| one-bit signature change with refreshed manifest identity | `signature.invalid` |
| keyid mismatch | `signature.malformed` |
| manifest-order plus signature-bitflip multi-defect | `manifest.invalid` |

The payload-byte mutation tests exact PAE binding: the modified payload remains a valid carrier member, but the original signature no longer verifies over the recomputed PAE.

The multi-defect vector declares:

```text
manifest.invalid
signature.invalid
```

All routes must return the first class.

## Routes

The required routes remain:

```text
reference-python-openssl
independent-go-stdlib

```

The external route participates at its P1-A2 and pre-COSE DSSE boundary. No `go-cose` invocation is claimed for A7.4.

## Deterministic generation

The corpus fixes source identities and ordered mutation sequences. The replay generates every vector twice and requires byte equality before executing any route. Generated outputs are derived evidence, not a second manually synchronized manifest.

## Canonical replay

The canonical result contains:

```text
1 positive carrier x 3 routes = 3 observations
9 negative vectors x 3 routes = 27 observations
total = 30 observations
```

Portable equality covers decision, error class and first failing boundary. Human-readable library errors and internal parser control flow are excluded.

## Claim boundary

A valid Ed25519 signature proves only verification against the supplied public key and exact PAE bytes. It does not establish signer trust, authorization, real-world identity, key custody, EIGIIB claim truth, transparency inclusion, trusted time or production interoperability.

P1-A7.4 does not close deterministic CBOR, COSE protected-header, COSE critical-header or Receipt negative families. Those remain subsequent P1-A7 obligations.
