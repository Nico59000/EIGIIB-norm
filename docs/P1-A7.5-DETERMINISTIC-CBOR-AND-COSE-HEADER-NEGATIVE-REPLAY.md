# P1-A7.5 — Deterministic CBOR and COSE Header Negative Replay

P1-A7.5 is an additive negative-replay slice within P1-A7. It preserves the exact A7.1 through A7.4 artifacts and introduces a separate corpus for deterministic CBOR, tagged COSE_Sign1 structure, protected headers and critical headers.

## Positive source

The positive carrier is the exact Signed Statement stored inside:

```text
tests/fixtures/p1-a3/capsule.json
```

Its COSE_Sign1 identity is:

```text
bytes: 396
sha256: 27c960d31e9afbf454c8bb6dbdd396309b3dec629f58d8f5c87553864e579d81
```

The supplied issuer SubjectPublicKeyInfo identity is:

```text
bytes: 44
sha256: 66ce2b50279d0f955a2e73434560439e4e47bfa6d6f365f8a83493510e97f447
```

The source capsule is parsed as strict JSON, the Signed Statement is decoded from canonical base64, both inner identities are re-observed, and the positive signature is verified before negative vectors are generated.

## Closed boundary order

Every route applies the following portable boundary order:

```text
top-level deterministic CBOR
COSE_Sign1 tag and four-element structure
protected-header deterministic CBOR
payload deterministic CBOR
closed protected-header and critical-header profile
Ed25519 verification over the exact COSE Sig_structure
```

A non-deterministic encoding is rejected before the semantic COSE header profile is evaluated. A malformed critical carrier is structurally invalid. A well-formed but unknown critical label is unsupported.

## Closed protected-header profile

The positive protected map contains exactly:

```text
1   alg = -8 (EdDSA)
3   content type = application/cbor
4   key id = SHA-256 of supplied issuer SPKI
15  CWT claims with exact issuer and string subject
16  type = application/scitt-statement+cose
```

Header label `2` (`crit`) is absent in the positive fixture. If present in a negative vector, it must be a non-empty array of integer labels. Unknown critical labels map to `cose.unsupported-header`; malformed `crit` carriers map to `cose.invalid-structure`.

## Negative corpus

The corpus contains nine vectors:

```text
a7-cbor-sign1-nonminimal-tag
a7-cbor-protected-map-order
a7-cbor-payload-map-order
a7-cose-wrong-tag
a7-cose-protected-not-bstr
a7-cose-unsupported-algorithm
a7-cose-unknown-critical-header
a7-cose-malformed-critical-header
a7-multi-cbor-order-and-unknown-critical
```

The first three exercise deterministic encoding at the outer Sign1, protected-map and payload-map boundaries. The next two exercise tagged structure. The following three exercise the closed algorithm and critical-header profile.

The multi-defect vector first adds critical label `999`, then reverses protected-map order. Its declared precedence is:

```text
cbor.nondeterministic
cose.unsupported-header
```

The required result is `cbor.nondeterministic` at `cbor-protected-header`.

## Route implementations

```text
tools/eigiib_p1_a7_cose_adapter.py
independent/p1cose/adapter.go
external/p1cose/adapter.go
```

The reference route uses a dependency-free CBOR codec plus OpenSSL Ed25519 verification. The independent route uses a separate Go standard-library CBOR codec and `crypto/ed25519`. The external route uses `fxamacker/cbor` for deterministic replay and invokes `go-cose` for the positive COSE_Sign1 verification after the portable CBOR and header gates pass.

External-library rejection text is not part of portable equality. Only acceptance, portable class and boundary are compared.

## Canonical replay

The canonical report contains:

```text

30 observations
```

Every A7.5 workflow run first replays A7.1, A7.2, A7.3 and A7.4. This detects accidental regression of an earlier slice before the new COSE replay is accepted.

## Claim boundary

P1-A7.5 closes only the bounded Signed Statement CBOR and COSE header profile described here. It does not establish source authenticity, trusted or authorized issuer identity, production interoperability, universal deterministic-CBOR equivalence, Receipt proof validity or complete P1-A7 closure.
