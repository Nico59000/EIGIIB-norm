# P1-A7.7 — Full Corpus Freeze, Cross-Platform Reproducibility and Authority Registration

## Decision

P1-A7.7 freezes the complete portable negative-corpus authority produced by P1-A7.1 through P1-A7.6. It does not add a new negative family. It registers the exact corpus, the exact prior canonical reports, the tested source commit and the distribution context required to reproduce the closure.

## Two distinct identities

The closure deliberately separates:

1. a common semantic authority, which must be identical on every route and platform;
2. a platform attestation, whose executable paths and binary SHA-256 values are expected to differ.

Binary inequality across Ubuntu, macOS and Windows is therefore not a replay divergence. A difference in the canonical authority report is a divergence.

## Source authority

The source authority is the exact P1-A7.6 commit:


The A7.7 verifier requires this commit to be an ancestor of the tested head. It also resolves every frozen path at that commit and compares the resulting Git blob identity with the manifest.

The entries are sorted by repository-relative path. The root carrier is:

```text

  "EIGIIB-P1-A7 authority-root v1\n" ||

```

The registered root is:


The outer SHA-256 protects the ordered authority carrier. The inner Git blob identities bind the exact repository bytes in the source commit. This registration does not claim a repository object format stronger than the Git object format used by the repository.

## Distribution policy

The closure policy fixes:

- CPython 3.13.14;
- Go 1.26.5;
- the exact checkout, setup-python and setup-go action commits;
- each runner label, architecture and image version;
- the observed OpenSSL and Git versions.

Each runner records SHA-256, byte length and resolved path for Python, Go, OpenSSL and Git. These platform attestations are intentionally not merged into the common report.

## Reproducibility gate

Each required runner performs, in order:

1. exact head checkout with full ancestry;
2. exact toolchain setup;
3. Python and Go adapter tests;
4. exact A7.1 through A7.6 replay;
5. source-commit and frozen-blob verification;
6. frozen-count verification;
7. toolchain-policy verification;
8. exact comparison with the A7.7 canonical report;
9. platform-attestation emission.

The common report is canonical JSON and must be byte-identical on Ubuntu 24.04, macOS 15 and Windows 2025.

## Claim boundary

P1-A7.7 establishes a repository-scoped authority for the closed fixtures and tested distributions. It does not establish production-input coverage, universal parser equivalence, universal Receipt interoperability, trust or authorization in supplied keys, trust in a transparency service, or global append-only consistency.

A later toolchain or distribution change is not silently assimilated. It requires a new authority revision and replay.
