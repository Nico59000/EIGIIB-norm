# M0-A9 Human Mastery Guide

## Reading the index

Start with `conformance/m0-a9-cross-lineage-capabilities.json`.

For every capability, verify four coordinates before interpreting the claim:

1. exact canonical head;
2. exact state path;
3. exact standard;
4. exact boundary.

The `established` list states what may be reused as a precedent. The `forbidden_inferences` list states what must not be derived from it.

## Applying a capability

A capability marked as a promotion target is not already promoted. A later slice must:

- bind a new exact artifact;
- execute the named operation;
- capture new evidence;
- retain the original nonclaims;
- freeze its own authority.

## Current decisions

M0-A10 may begin as a bounded implementation. E17 may not be adopted from M0-A9 alone.

A GitHub Release or OCI object observed now does not establish future availability. A signed retention policy does not prove platform enforcement. Distinct declared roles or services do not prove real administrative, organizational or failure-domain independence.

## Review rule

Reject any proposal that replaces an exact source head, changes a source boundary, removes a nonclaim, treats a policy as fulfilled, or promotes a P1 result into E15/E16 without a new exact operation.
