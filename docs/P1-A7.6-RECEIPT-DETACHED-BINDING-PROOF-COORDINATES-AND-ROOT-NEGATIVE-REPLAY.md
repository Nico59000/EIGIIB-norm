# P1-A7.6 — Receipt Detached Binding, Proof, Coordinates and Root Negative Replay

P1-A7.6 is the final negative-family slice currently planned inside P1-A7. It preserves the exact A7.1–A7.5 closures and adds a separate Receipt carrier, corpus, adapter set and canonical replay.

## Derived carrier

The A7.6 carrier contains exactly:

```text
standard
profile
binding
signedStatement
receipt
publicKeyPem
```

The binding fixes the declared tree size, leaf index and exact source Signed Statement identity. The Signed Statement and Receipt carriers each include canonical base64 and an observed SHA-256 identity.

## Portable boundary order

Every route evaluates:

```text
strict Receipt carrier and identities
outer deterministic Receipt CBOR
COSE_Sign1 tag, array, detached payload and headers
exact source Signed Statement binding
proof structure and sibling width
proof-versus-carrier coordinates
RFC9162_SHA256 root reconstruction
Receipt signature over the detached root
```

Earlier boundaries are authoritative. A malformed COSE structure cannot be replaced by a later proof or root failure.

## Bounded proof algorithm

The leaf hash is:

```text
SHA-256(0x00 || signed_statement)
```

Each proof node is:

```text
SHA-256(0x01 || left || right)
```

The side is derived from the leaf index. Siblings must be 32-byte strings, and the path length must match the declared tree size and leaf index. The corpus exercises one-entry and two-entry trees only; this does not claim universal Receipt proof coverage.

## Negative vectors

The corpus contains ten vectors:

```text
a7-receipt-embedded-payload
a7-receipt-detached-statement-bitflip
a7-receipt-proof-array-short
a7-receipt-proof-extra-sibling-one-entry
a7-receipt-proof-sibling-length
a7-receipt-leaf-index-out-of-range
a7-receipt-binding-proof-coordinate-mismatch
a7-receipt-two-entry-right-sibling-root
a7-receipt-two-entry-left-sibling-side
a7-multi-receipt-wrong-tag-and-root
```

The two-entry vectors have structurally valid coordinates and sibling widths. They reach root computation and fail because the original Receipt signature is not valid for the changed root.

## Multi-defect precedence

The multi-defect vector contains both a wrong COSE tag and a valid-shape two-entry proof that would lead to a different root. Its declared precedence is:

```text
cose.invalid-structure
receipt.invalid-proof
```

The required result is `cose.invalid-structure` at `receipt-cose-structure`.

The external route invokes `go-cose` after the portable carrier, CBOR, COSE, binding, proof and coordinate gates pass. It sets the detached root as the message payload before verification, matching the P1-A3 external observation route.

## Canonical replay

```text
1 positive carrier x 3 routes = 3 observations
10 negative vectors x 3 routes = 30 observations
total = 33 observations
```

The canonical report requires positive acceptance, complete negative rejection, portable class and boundary equality, and multi-defect precedence equality.

## Closure boundary

P1-A7.6 closes the bounded Receipt detached-binding, proof-shape, sibling-width, coordinate, side and root families. It does not establish trust in the transparency service, global append-only log consistency, production-input coverage, universal Receipt interoperability, reproducible toolchain identity or the final complete P1-A7 authority freeze.
