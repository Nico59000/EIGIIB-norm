# M0-A7 Human Mastery Guide

## Purpose

M0-A7 is the transition gate between the closed E15 lineage and a possible E16 preservation lineage. It is repository infrastructure, not an E16 adoption.

## What is already closed

E15-A5 head `036b81c3c128524858d66d096a1eb87e23cc5dad` is conformant on Ubuntu 24.04, macOS 15 and Windows 2025. Its 86-authority freeze is the only source for E16 entry.

## What E16 would add

E16 would reason about bounded external preservation after E15 publication:

```text
preservation intent
  -> custodian and replica binding
  -> placement and acceptance evidence
  -> bounded retention observations
  -> independent readback and restore
  -> migration, quarantine or succession
```

## What must remain separate

- publication is not replication;
- a replica locator is not custody acceptance;
- custody acceptance is not future retention;
- readback is not restore completion;
- one restore is not future restorability;
- two labels are not independent failure domains;
- one deletion is not global erasure.

## Maintainer decision

Approve M0-A7 only when:

1. all E15 frozen paths are byte-identical;
2. both E15 three-platform matrices are recorded as successful;
3. E16 remains unadopted;
4. no E16 implementation artifact exists;
5. the A1–A5 plan preserves bounded claims and negative precedence.

The next authorized action after M0-A7 is E16-A1, which must replay E15 historically before changing the central profile.
