# P1-A7 — Differential Negative Corpus and Parser-Ambiguity Closure

P1-A7 is an additive interoperability profile outside the numbered `E*` chain. It consumes the validated P1-A5 and P1-A6 routes and introduces a portable negative corpus shared by the Python reference route, the independent Go route and the external native observation.

## Target condition

Every closed vector must produce the same portable decision on every required route:

```text
same acceptance or rejection
+ same portable error class
+ same precedence when several defects coexist
```

Human-readable messages, stack traces and library-specific errors are not compared.

## Route set

The initial required route set is:

```text
reference-python-openssl
independent-go-stdlib
external-go-cose
```

A route that is unavailable, silently normalizes a forbidden encoding or returns an unmapped implementation error is non-conformant.

## Negative layers

The corpus is partitioned by the first authoritative boundary expected to reject the input:

| Layer | Initial mutation families |
| --- | --- |
| JSON | duplicate members, non-finite numbers, invalid UTF-8, trailing data |
| Base64 | non-canonical alphabet, invalid padding, truncated value |
| Path | absolute path, traversal, symlink, non-regular file |
| Manifest | duplicate member, permutation outside the declared canonical order, wrong length, wrong digest |
| DSSE | truncated signature, wrong payload type, wrong pre-authentication encoding |
| CBOR | non-deterministic integer or length encoding, duplicate map key, forbidden indefinite length |
| COSE | unknown critical header, unsupported algorithm, wrong tag, malformed protected header |
| Receipt | detached-payload mismatch, malformed proof, wrong tree coordinates, wrong root binding |
| Projection | missing field, extra field, wrong result carrier, chain-identity divergence |

## Portable error classes

The authoritative taxonomy is `tests/fixtures/p1-a7/error-taxonomy.json`. It assigns every portable class to one layer and one unique precedence rank.

The precedence rule is:

```text
lowest-rank-first-authoritative-boundary
```

A multi-defect vector must list all expected classes in taxonomy order. The first listed class is the required portable result. Incidental parser order is never authoritative.

Human-readable messages and implementation-specific exceptions remain outside the portable carrier.

## P1-A7.1 — schema, taxonomy and deterministic generator

P1-A7.1 closes the structural input to later differential replay. It does not yet implement the three route adapters.

The closed artifacts are:

```text
schemas/eigiib-p1-a7-negative-vector.schema.json
schemas/eigiib-p1-a7-error-taxonomy.schema.json
tests/fixtures/p1-a7/error-taxonomy.json
tests/fixtures/p1-a7/corpus.json
tests/fixtures/p1-a7/source/generator-seed.json
tools/eigiib_negative_vector_generator.py
```

The generator uses only the Python standard library. JSON-producing mutations are serialized as UTF-8 with sorted keys, two-space indentation and one terminal LF. JSON pointers follow RFC 6901.

The initial operator set is:

```text
raw.insert-hex
raw.append-utf8
json.duplicate-root-member
json.set
json.delete
json.append-string
```

Every source fixture and every generated output is bound by SHA-256 and byte length. The generator refuses:

- missing, absolute, escaping, symlinked or non-regular source paths;
- source or taxonomy identity mismatches;
- duplicate vector identifiers;
- unknown operators or portable classes;
- non-contiguous or duplicate taxonomy precedence ranks;
- precedence lists that do not follow the taxonomy;
- generated bytes that differ from the recorded identity.

These vectors prove deterministic construction and identity closure only. Their expected portable classes are target obligations for later route adapters, not observed three-route results.

## Vector contract

Each vector declares:

```text
id
layer
source path and exact identity
mutation operation
expected rejection
expected portable error class
precedence list
required routes
required platforms
claim boundary
generated exact identity
```

Mutated fixtures are generated deterministically from checked-in source fixtures. Generated binary outputs do not need to be checked in because the manifest binds their exact bytes and the generator can reproduce them.

## Closure requirements

P1-A7 is complete only when:

- the positive corpus remains conformant on all routes;
- every negative vector is rejected by every required route;
- every rejection maps to the same portable error class;
- multi-defect precedence is explicit and equal across routes;
- Linux, macOS and Windows results agree;
- corpus identities and generation procedures are closed;
- no route silently repairs forbidden input;
- residual parser or library divergences are recorded rather than normalized away.

P1-A7.1 satisfies only the schema, taxonomy and generator portion of these obligations.

## Claim boundary

P1-A7 establishes portable parser and verifier behavior only for the closed fixtures, mutations, routes, versions and platforms. P1-A7.1 does not imply route-adapter implementation, observed rejection, error-class equivalence, universal parser equivalence, memory safety, production trust, complete fuzzing coverage, semantic truth of claims or closure of the reproducible toolchain obligations assigned to P1-A8.
